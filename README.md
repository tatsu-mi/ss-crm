# Tatsumi SS CRM

顧客・エンジニア・契約・商談・活動・タスクを同じワークスペースで管理するSES向けCRM。Next.js App Router、React、TypeScript、Supabaseで構成し、Vercelでの実行を想定しています。

業務データは専用テーブルと外部キーで管理します。業務上の名称を「契約」に統一し、1契約に1エンジニアを紐づけます。条件はエンジニア別の契約期間ごとに保持し、通常の列や関連テーブルの追加で今後の機能追加に対応します。

## ローカルで起動

Node.js 22以上を使用します。

```bash
npm ci
cp .env.example .env.local
npm run dev
```

http://localhost:3000 を開きます。Supabaseの公開接続情報が両方とも未設定ならデモモードで起動します。デモの変更はブラウザのLocal Storage（`nexus-crm-demo-v6`）に保存されます。このキーを削除すると初期状態に戻ります。

デモモードではチーム共有や画面を閉じている間の通知処理は行いません。Supabase接続後はDBのデータを表示し、デモデータを自動送信しません。

## Quick Tunnelで一時公開

Linux・macOS・WSLで利用できます。Node.js 22以上と[cloudflared](https://developers.cloudflare.com/tunnel/downloads/)をインストールし、初回は`npm ci`を実行してください。Supabaseを使う場合は、下記の手順で`.env.local`とDBを準備します。

```bash
npm run share
```

毎回本番ビルドを作成し、CRMを`127.0.0.1:3000`で起動してからQuick Tunnelを開始します。ログに表示される`https://….trycloudflare.com`が公開URLです。Cloudflareアカウント・ドメイン購入は不要で、既存のcloudflared設定ファイルも変更しません。Ctrl+Cでアプリとトンネルの両方を停止します。

3000番ポートが使用中なら、別のポートを指定できます。

```bash
PORT=3001 npm run share
```

コードや`.env.local`の変更を反映するときは、実行中のターミナルで`r`を入力してEnterを押します。Quick Tunnelを動かしたまま、CRMだけを停止・再ビルド・再起動するので、公開URLは変わりません。更新中は一時的にアクセスできなくなります。ビルドに失敗した場合もトンネルを維持するので、修正後に`r`とEnterで再試行できます。

URLはQuick Tunnelの起動ごとに変わり、PCのスリープやプロセス終了でアクセスできなくなります。Quick Tunnelは一時共有用で、稼働時間の保証はありません。URLを知っている人はログイン画面（デモモードならデモ画面）へアクセスできます。デモモードのデータはブラウザごとの保存で、共有されません。

ローカル実行では`vercel.json`のCronは動きません。定期通知が必要なら、別途スケジューラーから`CRON_SECRET`のBearer認証付きで`/api/cron/reminders`を呼び出します。

## Supabaseの準備

空のSupabaseプロジェクトを用意してください。開発中のスキーマ変更は初期マイグレーション1本に反映します。

1. SQL Editorで[初期マイグレーション](supabase/migrations/202610190001_crm.sql)を実行します。開発中はこの1本を最新スキーマに更新し、変更後のDBは再作成します。
2. [標準活動種別・活動テンプレート](supabase/seed.sql)を実行します。業務サンプルデータは入りません。
3. AuthenticationのUsersからアカウントを作り、SQL Editorで利用者を登録します。

```sql
insert into public.app_users(id, display_name, role)
select id, '佐藤 花子', 'admin'
from auth.users
where email = 'you@company.jp';
```

メールアドレス・表示名は実際の値に置き換えてください。`role`は`admin`または`member`で、現在は両方とも標準の業務操作ができます。利用者の追加・停止・パスワード再設定はSupabase管理画面とSQL Editorで行います。`app_users`未登録、または`disabled_at`を設定したアカウントはCRMを利用できません。

1つのSupabaseプロジェクトを1つの共有ワークスペースとして扱います。登録されたメンバーは原価を含む業務データを共有し、通知は本人宛だけを参照できます。RLSで読み取りを制御し、書き込みは検証と履歴保存を行う専用RPCに限定します。

### アプリの接続設定

`.env.local`に次を設定して再起動します。

```dotenv
NEXT_PUBLIC_SUPABASE_URL=https://YOUR_PROJECT.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=YOUR_PUBLISHABLE_OR_ANON_KEY
SUPABASE_SERVICE_ROLE_KEY=YOUR_SERVICE_ROLE_KEY
CRON_SECRET=YOUR_RANDOM_SECRET
SANSAN_API_KEY=YOUR_SANSAN_API_KEY
```

サービスロールキーはサーバーの通知処理だけに使います。`NEXT_PUBLIC_`を付けず、Gitに保存しないでください。

Sansan連携を使う場合は、API利用権限と必要な名刺への参照権限を持つSansanユーザーのAPIキーを `SANSAN_API_KEY` に設定します。キーはサーバー側だけで使用します。取得範囲はそのユーザーが参照できる名刺に限られます。デモモードでも実際のSansan APIから登録日時の新しい順に名刺を最大10件取得し、取り込み結果と連携状態はブラウザ内に保存します。事業部・社員の絞り込みはその10件に対して行います。デモモードで利用するには `SANSAN_DEMO_PASSWORD` に推測されにくい英数字を設定し、画面に入力します。パスワードはSansan APIキーとは別の値にしてください。

## 操作

「Sansan連携」から名刺を取得する前に、取込元の事業部（配下の部署を含む）や名刺所有者を選べます。事業部・社員の絞り込みはSansanから名刺を取得した後に行うため、APIからの取得量は減りません。事業部は名刺所有者の現在の所属から判定し、Sansanシステム管理者権限を持つAPIキーが必要です。会社ごとに新規取引先を作成するか既存取引先に紐づけ、担当者の取込先を確認します。既存取引先の候補がない会社は複数選択して一括新規取り込みできます。CRMの営業担当は自動設定しません。連携済み会社の後続の担当者追加や変更の取り込みにはまだ対応していません。

画面は[モック](docs/mock.png)に合わせ、上部に取引先一覧、下部左に基本情報・担当者、右に表形式の活動を配置します。取引先一覧にはWebサイト・電話番号・業種・所在地・担当者数・稼働エンジニア数・進捗状況・最終活動日・更新日・営業を表示します。

- 値のセルをダブルクリック、Enter、F2、または文字入力で直接編集できます。Enter・Tab・セル外へのフォーカス移動で保存し、Escで取り消します。選択中のセルは矢印キーで移動できます。
- 入力エラーや同時編集の競合時は、保存せず入力内容を残します。人数・更新日などの集計項目は読み取り専用です。
- 基本情報にはふりがな・従業員数・設立年月・売上規模も表示します。担当者・契約・商談・活動・タスクの各表でもセルを直接編集できます。
- 契約タブで契約、取引先詳細の「参画エンジニア」タブで参画エンジニア・契約期間を管理します。商談は活動の種別から確認します。
- 契約の登録・編集でエンジニアを1人選択できます。紐づけは契約本体と一括保存し、解除後も期間と条件を保持します。再度紐づけると同じ参画情報を復元します。
- 上部の「エンジニア」は登録済み全員の一覧です。活動の「関連エンジニア」の選択肢もこの一覧を参照します。
- 契約の「複製」は標準項目と最新の契約期間・単価・原価を下書きにコピーします。エンジニアと条件を編集して保存でき、活動・タスク・履歴は引き継ぎません。
- 取引先詳細の「参画エンジニア」は契約・エンジニア・契約期間を結合した表です。請求単価・原価・日付はエンジニア別の契約期間へ、営業は契約へ保存します。「更新」は次の期間を追加し、以前の条件を残します。
- 新規登録、参加者などの複数項目の編集、変更履歴、削除・復元は、行のメニューから詳細画面で操作できます。 削除済みのデータは、削除範囲を確認したうえで完全に削除できます。関連データや変更履歴も削除され、復元できません。
- 活動の「関連活動」は同じ顧客の他の活動を複数選択でき、「関連契約」と別列で表示します。
- 活動の内容はMarkdownで入力・保存します。保存済みのテンプレートを挿入でき、内容セルから開くダイアログで編集・プレビューできます。
- 右上の歯車アイコンから設定メニューの「活動テンプレート」を選ぶと、テンプレートの追加・編集・削除ができます。削除したテンプレートは復元できません。テンプレート名とMarkdown本文はDBで共有し、商談・面談・その他の初期テンプレートも編集できます。テンプレートの変更は入力済みの活動本文に影響しません。
- 活動の種別タブと関連リンクで履歴を絞り込めます。取引先一覧の検索・絞り込みと選択を保ったまま更新できます。

## 配置と通知

Vercelにインポートし、Framework PresetをNext.js、Node.jsを22以上に設定します。上記4つの環境変数を配置先へ設定してください。公開環境ではSupabaseの公開接続情報を両方設定します。

`vercel.json`は毎日00:00 UTC（日本時間09:00）に`/api/cron/reminders`を呼び出します。`CRON_SECRET`のBearer認証とサービスロールでDBの通知関数を実行します。一般利用者には通知関数の実行権限を付与していません。

通知はアプリ内通知です。契約終了30日前から営業への更新通知と確認タスクを作成し、タスクの期限7日前から前日までの通知、および当日の通知を生成します。期間・状態・担当者の最新値を使い、同じ通知機会での再実行やタスク作成は重複しません。営業のない契約期間はスキップ理由を処理結果に返します。通常画面は1分ごとに最新データを取得します。

## 検証

```bash
npm run typecheck
npm test
npm run test:db
npm run build
```

DBテストはPGliteの一時PostgreSQL環境で新規スキーマ、外部キー、顧客整合性、契約期間の重複、同時編集検出、履歴、削除復元、参加者の一括保存、RLS、RPC権限、通知の再実行を確認します。外部のSupabase接続は不要です。

ブラウザテストはデモモードで実行します。

```bash
npx playwright install chromium
npm run test:e2e
```

必要なら`PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`でブラウザを指定できます。

参画エンジニアの契約名は紐づく契約を開く参照表示とし、この一覧からは手入力で変更しません。顧客の連絡先は「担当者」、自社の利用者は「営業」と表記します。

活動種別は「商談」「面談」「その他」の3つです。開発中は既存データの移行処理を設けず、DBの定義は初期マイグレーション1本にまとめます。旧形式のデモデータは読み込まず、現在の形式で初期化します。

活動種別の「面談」は、エンジニアが参画するために顧客と行う面談を指します。顧客との相談・提案・条件調整は「商談」、参画後のフォローやフィードバックなどは「その他」として記録します。

活動の関連エンジニアは名前で検索して追加し、選択済みの名前から解除できます。候補は未選択・利用中のエンジニアに絞り、検索結果は最大20件を表示します。キーボードの上下キー・Enterでも選択できます。
