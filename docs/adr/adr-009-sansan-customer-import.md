# ADR 009 Sansanの会社を確認して顧客に取り込む

## ステータス

採用

## 決定日

2026-10-30

## コンテキスト

Sansanの名刺から顧客と担当者を取り込みたい。CRMには既存顧客や担当者があり、会社名やメールアドレスの一致だけでは同一と確定できない。一方、初回は多数の会社を取り込むため、個別操作だけでは負担が大きい。

## 検討した選択肢

採用：未連携の会社を候補として示し、利用者が新規作成または既存顧客への紐づけを選ぶ。複数会社の一括新規作成も可能にする。

不採用：会社名やメールアドレスの一致だけで既存データに自動的に紐づける。誤った顧客や担当者に結びつける可能性がある。

## 決定事項

Sansan連携タブを設け、Sansanの名刺から会社単位の未連携候補を提示する。利用者は候補を絞り込み、会社ごとにCRMの顧客を新規作成するか、既存顧客に紐づけるかを選択できる。複数の候補を選んで新規顧客として一括取り込みすることもできる。

会社と顧客、および人物・名刺と担当者の対応を連携元の識別子とともに保持し、再取り込みや同時操作による重複作成を防ぐ。既存の担当者との対応は利用者が確認し、識別子や所属の変更など対応が不明な場合は確認対象とする。会社IDがないなど会社を識別できない名刺も自動的に会社へまとめない。

連携済みの会社に後から追加された担当者や変更は、会社の初回取り込みとは区別して扱えるようにする。Sansanで取得できなくなったことだけを理由にCRMの顧客や担当者を削除・アーカイブしない。

Sansanの名刺所有者とCRMの営業担当は別の概念として扱う。所有者は候補の絞り込みに利用できるが、CRMの営業担当に自動的に置き換えない。

## 決定理由

利用者が対応を判断することで、既存データへの誤った紐づけを避けられる。一括新規作成は初回の作業負担を抑えるが、重複候補の確認が必要になる。連携元との対応を保持することで、繰り返し取得した場合にも同じ会社や担当者を重複作成せず、後続の変化も識別できる。

## 結果

Sansanの会社をCRMの顧客へ段階的に取り込める一方、曖昧な候補には利用者の判断が必要になる。一括取り込みでは既存顧客との重複可能性を確認できるようにする。顧客・担当者と連携先の対応および変更履歴の保存には、既存の[アクセス境界](adr-006-database-access-boundary.md)と[トランザクション・競合制御](adr-007-transactional-integrity.md)の保証を適用する。
