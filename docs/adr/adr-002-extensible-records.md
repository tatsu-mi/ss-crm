# ADR 002 周辺情報を定義付きの共通記録で管理する

## ステータス

採用

## 決定日

2026-10-16

## コンテキスト

案件・商談・契約・活動などは、業務に応じて種類や項目を増やしつつ複数の画面から参照する必要がある。

## 検討した選択肢

採用：情報種別・項目定義・記録・参照の共通構造。

不採用：業務ごとの専用テーブル。種別の追加が開発に依存する。

不採用：定義のない自由記述やJSON。型や所有関係の意味を保証できない。

## 決定事項

周辺情報は情報種別、項目定義、記録、参照で表す。記録の所有先は顧客・エンジニア・関係のいずれか1つとし、参照と逆参照で共有する。画面別に記録を複製しない。共通記録を正本とし、検索用の派生データは再構築可能とする。

## 決定理由

中心の関係を保ちながら、業務ごとの情報追加をテーブル追加から切り離せるため。

## 結果

同じ記録を複数の画面から利用できる。共通の定義検証・権限制御・検索の設計が必要になる。検索負荷が増えた場合は索引や検索用テーブルを追加できるが、派生データを独立した入力先にはしない。
