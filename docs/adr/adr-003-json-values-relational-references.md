# ADR 003 単純値をJSONに参照を関連テーブルに保存する

## ステータス

採用

## 決定日

2026-10-16

## コンテキスト

項目を柔軟に追加したい一方、記録や利用者への参照には存在確認と削除時の整合性が必要になる。

## 検討した選択肢

採用：定義で検証するJSON値と、外部キーを持つ関連テーブルを組み合わせる。

不採用：参照も含めてすべて自由なJSONにする。参照整合性が弱くなる。

不採用：全項目を型別の値テーブルにする。初期段階から結合と更新処理が増える。

## 決定事項

テキスト・金額・日付などの単純値は項目定義に従って検証したJSONとして保存する。不変の項目キーを使い、表示名をキーにしない。記録参照と利用者参照は外部キーを持つ関連テーブルで保持する。項目定義による値の検証と、外部キーによる参照先の存在保証を分担させる。

## 決定理由

項目追加のたびにDB列を増やす負担を抑えつつ、関連先の存在と削除の扱いを確認できるため。

## 結果

拡張性と参照整合性を両立できるが、JSON値の検索と一意性の制御は複雑になる。
