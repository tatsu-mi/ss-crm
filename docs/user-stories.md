# SES向けCRM ユーザーストーリー

顧客を起点に、SES営業の日常業務をできるだけ1画面で完結させる。まず以下のストーリーを初期開発の対象とする。将来はエンジニアを起点とした確認にも広げる。

各ストーリーは「誰が・何をしたいか・なぜ必要か」と、実現できたことを確認する受け入れ条件で記載する。通知時期、原価の範囲、受注確度の運用などの詳細は、業務に合わせて決める。

## 顧客を把握する

### US-01 顧客を探して選択する

営業担当者として、顧客を検索・選択したい。連絡や訪問の前に、対象顧客の状況をすぐに把握するため。

受け入れ条件：

- 顧客名で検索し、取引状況や自社営業担当で絞り込める。
- 一覧で会社名、取引状況、自社営業担当、契約中のエンジニア人数、最終活動日を確認できる。
- 顧客を選択すると、その顧客の詳細と履歴を確認できる。

### US-02 顧客の基本情報を確認・更新する

営業担当者として、顧客の基本情報を登録・確認・更新したい。営業に必要な会社情報と取引状況を共有するため。

受け入れ条件：

- 会社名、ふりがな、Webサイト、電話番号、所在地、業種、従業員数、設立年月、売上規模、自社営業担当、取引状況、備考を管理できる。
- 詳細が分からなくても、会社名から登録を始められる。
- 取引状況と、個別の商談の進捗をそれぞれ確認できる。

### US-03 顧客側の担当者を管理する

営業担当者として、顧客の窓口となる担当者を管理したい。誰に、どの連絡先で連絡すればよいか分かるようにするため。

受け入れ条件：

- 1社に複数の担当者を登録できる。
- 氏名、部署、役職、メールアドレス、電話番号、主な窓口を確認・更新できる。
- やり取りの記録から、関わった顧客側担当者を確認できる。

## 案件と商談を進める

### US-04 顧客の案件を管理する

営業担当者として、顧客の募集案件や相談内容を管理したい。どの案件に、どのようなエンジニアを提案すべきか判断するため。

受け入れ条件：

- 顧客に案件を登録し、案件名、概要、必要スキル、募集人数、希望単価、参画予定日、募集状態を確認・更新できる。
- 詳細が未確定でも、案件名から登録を始められる。
- 同じ顧客の複数案件を確認でき、募集終了後も経緯を参照できる。

### US-05 商談ごとの進捗と受注確度を管理する

営業担当者として、案件に対する提案や商談の進捗と受注確度を管理したい。次に取るべき行動と、注力すべき商談を判断するため。

受け入れ条件：

- 商談に顧客、案件、候補エンジニアを関連付けられる。案件や候補が未確定でも登録できる。
- 商談ごとに自社営業担当、進捗段階、受注確度、見込金額、受注予定日、参画予定期間を確認・更新できる。
- 同じ案件への複数の提案・商談を区別できる。
- 進捗の変更経緯と、受注・失注の結果を確認できる。
- 受注した商談の情報を引き継いで契約を登録できる。

## やり取りと契約を管理する

### US-06 各種履歴を記録・確認する

営業担当者として、商談、提案、電話、訪問、面談、フィードバックなどの履歴を記録したい。顧客との経緯を把握し、引き継ぎにも使えるようにするため。

受け入れ条件：

- 日時、種別、タイトル、内容、記録担当者を登録・編集できる。
- 選択中の顧客に記録でき、必要に応じて案件、商談、契約、顧客側担当者にも関連付けられる。
- 顧客全体の履歴を時系列で確認し、種別や関連先で絞り込める。
- 履歴から次の対応タスクを登録できる。

### US-07 契約エンジニアの情報を管理する

営業担当者として、顧客に参画しているエンジニアと契約条件を管理したい。誰が、いつまで、いくらで参画しているか把握するため。

受け入れ条件：

- 顧客ごとに契約エンジニアの一覧を確認できる。
- エンジニア名、請求単価、原価、契約期間を確認・更新できる。
- 開始前、契約中、終了済みを区別できる。
- 対象エンジニアの契約に関する面談記録やフィードバックを確認できる。
- 同じ面談記録やフィードバックを、顧客全体の履歴からも参照できる。

### US-08 契約を更新して過去の条件を確認する

営業担当者として、契約を更新するときに以前の条件も残したい。期間、単価、原価の変更経緯を把握するため。

受け入れ条件：

- 更新前の条件を残したまま、次の契約期間と条件を登録できる。
- 過去と現在の契約条件を確認できる。
- 更新の確認状況と、更新予定・終了予定を確認できる。
- 更新に関する活動、タスクを対象の契約から参照できる。

## 次の対応を忘れない

### US-09 タスクとリマインダーを管理する

営業担当者として、次の対応、担当者、期限を管理し、期限が近づいたら知らせてほしい。顧客への連絡や社内対応を漏らさないため。

受け入れ条件：

- タスクに内容、担当者、期限、状態を設定できる。
- タスクを顧客に関連付け、必要に応じて案件、商談、契約、活動にも関連付けられる。
- 顧客ごとのタスクと、顧客を横断した自分の未完了タスクを確認できる。
- 期限前と期限到来時にリマインダーを受け取り、対象のタスクを開ける。
- 期限超過を識別でき、完了・取消したタスクのリマインダーは停止する。

### US-10 契約更新の自動通知を受け取る

営業担当者として、契約終了が近づいたら自動で知らせてほしい。更新確認と顧客調整を余裕を持って進めるため。

受け入れ条件：

- 契約終了までの所定の時期に、担当営業への通知と更新確認タスクが自動で作成される。
- 顧客や契約の画面を開いていなくても、通知の対象になる。
- 通知から対象の顧客、契約、更新確認タスクを開ける。
- 更新確認が未完了の場合は再通知を受け取れる。
- 更新・終了・担当変更を反映し、同じ確認タスクや通知が重複しない。

## 画面と情報管理を使いやすくする

### US-14 顧客の情報管理を1画面で完結する

営業担当者として、顧客を選んだまま関連情報を確認・更新したい。画面移動や顧客の探し直しを減らすため。

受け入れ条件：

- mock.pngを基準に、上部で顧客一覧、下部左で顧客詳細、下部右で活動履歴を確認できる。
- 基本情報、担当者、案件・商談、契約エンジニア、タスクを同じ画面内で切り替えて確認できる。
- 一覧・基本情報・担当者・案件・商談・契約エンジニア・活動・タスクのセルを直接編集でき、保存後も顧客の選択と一覧の検索条件を維持する。
- Enter・Tab・フォーカス移動で保存し、Escで取消できる。入力エラーや同時編集の競合時には入力内容を残し、保存済みの値を変更しない。
- 契約エンジニアはエンジニア・契約・契約期間を結合した表として表示し、内部テーブルの分割をそのままタブ構成にしない。
- 案件・商談・契約に関連する活動とタスクを絞り込み、顧客全体の表示へ戻せる。
- 顧客横断のタスクから、対応が必要な顧客を開ける。

## 将来的な展望

### US-16 エンジニアを起点に情報を確認する

営業担当者として、エンジニアを選んで提案先、契約、面談、フィードバックを横断して確認したい。そのエンジニアの経緯を踏まえて、次の提案やフォローを判断するため。

受け入れ条件：

- エンジニアから、関連する顧客、商談、現在と過去の契約を確認できる。
- 顧客側で登録した面談記録やフィードバックを、エンジニア側からも参照できる。
- 顧客軸とエンジニア軸の画面で、同じ情報を再入力せずに扱える。

このストーリーの画面は将来の対象とし、初期開発では顧客を起点とした管理を優先する。
